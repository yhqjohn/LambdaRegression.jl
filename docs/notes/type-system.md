# Type System

The language is a lambda calculus checked by rank-1 Hindley–Milner inference.
Bound variables may use De Bruijn indices, so binder names do not affect
meaning.

```text
M, N ::= x | #i | c | λx. M | M N
let x = N in M  ≡  (λx. M) N
```

Types are generated by:

```text
τ ::= α | κ | τ → τ | τ × τ | τ + τ
    | List τ | Array[ℓ, τ] | μ α. τ
ℓ ::= n | αℓ
σ ::= τ | ∀α₁ … αₙ. τ
```

`κ` is an atom and `ℓ` is an array length. A recursive occurrence is guarded
by a type constructor. `Γ` maps local variables or indices to schemes; `Σ`
maps constants to closed types or explicit schemes. Scheme use creates fresh
instances.

The typing judgment is `Σ ; Γ ⊢ M : τ`. Variables and constants are looked up,
abstractions introduce a fresh argument type, and applications unify the
function type with `argument → result`. At a let-like application, the bound
term is inferred first, then variables absent from the surrounding environment
are generalized.

Unification decomposes matching constructors, including products, sums, lists,
and arrays. A guarded equation may denote a recursive type; a naked self
equation is invalid. Typing does not imply termination.

Container operations are typed constants: products and sums have constructors
and eliminators; lists have empty and cons forms; arrays have length-preserving
map, fold, and list conversion operations. Concrete primitive catalogs are
outside this abstract contract.
